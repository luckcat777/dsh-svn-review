# JavaScript / TypeScript 语言档案（languages/javascript.md）

> **L1 语言档案。** 适用条件：代码是 JavaScript、TypeScript、Node.js 或浏览器端脚本。
>
> 三层分工与优先级同 `java.md` 开头：**L2 项目约定 > 本文件 > L0 默认判断**。

---

## 1. 适用范围与版本约束

**先确认四件事**：

1. **运行环境**：Node 还是浏览器？Node 版本？有没有 bundler？
2. **模块格式**：ESM（`import`）还是 CJS（`require`）？两者不能混用同一文件。
3. **TypeScript 与否**：`.ts` 且 `strict` 开启时，大量空值检查已由编译器保证 —— 此时再提"可能 undefined"多为误报。
4. **目标语法级别**：是否经过 Babel/TS 编译降级（影响 `?.`、`??` 能否直接写）。

---

## 2. 语言惯用法（审查前必须理解）

**JS 是单线程事件循环。** 没有数据竞争，但有**交错**：任何 `await` 之后，共享状态可能已被其他任务改掉。这一条是 JS 与 Java/C++ 最本质的差异：

- ❌ 不能说「建议加锁保证线程安全」——没有线程。
- ✅ 可以说「`await` 之间读到的值可能已过期」——但必须指出**谁会改它**。

**假值（falsy）**：`0`、`''`、`null`、`undefined`、`NaN`、`false` 都为假。因此 `if (obj.value)` 会把合法的 `0` 和 `''` 当成"没值"——这是 JS 独有的高发缺陷。

**动态类型**：类型错误在运行时才暴露，且往往表现为"某个字段静默变成 `undefined`"，而不是抛异常。

## 3. 常见确定性缺陷（P1 候选）

### 3.1 异步

| 模式 | 后果 |
|---|---|
| `async` 函数调用未 `await` | 返回 Promise 被丢弃，异常变成 unhandledRejection |
| `forEach(async ...)` | `forEach` 不等待，循环在第一个 `await` 处就"结束"了 |
| `new Promise` 里 `throw` 但没 `reject` | 外层永远 pending |
| `try-catch` 包住的是 `promise` 的创建而非 `await` | 异步错误逃出 catch |
| 并发读改写：`await get()` → 计算 → `await set()` | 中间被别的任务插入，覆盖丢失 |
| 未 `return` 的 `.then()` 链 | 后续无法等待 |

### 3.2 相等与类型

| 模式 | 后果 |
|---|---|
| `==` 比较 | `'0' == false`、`null == undefined` 为真，隐式转换导致意外分支 |
| `typeof null === 'object'` | 用 `typeof` 判空失效 |
| `NaN === NaN` 为 `false` | 比较永远不成立，应 `Number.isNaN` |
| `parseInt('08')` / `parseInt('10px')` | 无基数或部分解析，结果意外 |
| 整数超过 `2^53` | 精度丢失（ID、金额、时间戳微秒） |
| `0.1 + 0.2 !== 0.3` | 金额用浮点必然出错，应整数分或 `decimal` |

### 3.3 集合与对象

| 模式 | 后果 |
|---|---|
| `[1,10,2].sort()` | 默认按字符串排序，得到 `[1,10,2]` |
| `Array(3).map(...)` | 稀疏数组，`map` 不执行回调，得到空数组 |
| `for...in` 遍历数组 | 会遍历到原型链和字符串键 |
| `delete arr[i]` | 留下 `hole`，`length` 不变 |
| `JSON.parse` 未 `try` | 非法输入直接抛，中断整个流程 |
| 合并用户可控对象（`Object.assign`/深拷贝） | `__proto__` 原型污染 |
| 深拷贝 `JSON.parse(JSON.stringify(x))` | 丢 `Date`/`undefined`/函数，循环引用直接抛 |

### 3.4 作用域与绑定

| 模式 | 后果 |
|---|---|
| `var` 在循环里创建闭包 | 所有闭包共享同一个变量，拿到最后的索引 |
| 方法作为回调传递（`this.fn` 传出去） | `this` 丢失，运行时 `undefined` |
| 正则带 `g` 标志复用 | `lastIndex` 累积，第二次 `test` 结果错误 |

### 3.5 资源与内存

| 模式 | 后果 |
|---|---|
| `addEventListener` / `setInterval` 未清理 | 组件销毁后仍持有引用，泄漏 |
| 大 Buffer/闭包长期驻留 | 堆增长，最终 OOM |
| `fs` 流错误未监听 `'error'` | 进程直接崩溃 |

## 4. 误报清单（不得提出的意见）

> 这一节对 JS 尤其重要：通用 LLM 会把 Java/C++ 的直觉套过来，产生大量无效建议。

### 4.1 语言模型误判

- ❌ 「建议加锁 / 用 `Mutex` / 保证线程安全」
  → JS 单线程，没有锁。真正的风险是 `await` 交错，说法完全不同。
- ❌ 「这里可能 `undefined`，建议判空」
  → 若已用 `?.` / `??` / 默认参数，或 TS `strict` 已保证非空，则不成立。必须指出**哪条路径**能让它为 `undefined`。
- ❌ 「建议给参数加类型注解」
  → 纯 JS 项目（无 TS）里不可执行；有 TS 项目里则编译期已保证。
- ❌ 「建议 `var` 改成 `let`」
  → 若已经是 `let`/`const`，纯属幻觉。
- ❌ 「建议用 `===` 替代 `==`」
  → 若代码里就是 `===`，属于没看清代码。另外 `x == null` 同时匹配 `null` 和 `undefined`，是**惯用写法**，改成 `=== null` 反而漏掉 `undefined`。
- ❌ 「建议加 try-catch」
  → 必须说明 catch 在哪个位置、捕获哪个异常。异步异常必须落在 `await` 处，加错地方等于没加。

### 4.2 风格伪装成缺陷

- ❌ 「建议把回调改成 `async/await`」
  → P3 偏好，且改造可能改变错误传播路径。
- ❌ 「建议 `forEach` 改成 `for...of`」
  → 除非回调是 `async`（那是真缺陷），否则属风格。
- ❌ 「建议用 `const`」
  → P3，不进报告。
- ❌ 「`innerHTML` 有 XSS 风险」
  → 必须给出**用户可控输入到达该行**的路径。写死的模板字符串不成立。
- ❌ 「建议引入 lodash / TypeScript / 某框架」
  → 新依赖不在 diff 审查范围。

### 4.3 性能

- ❌ 「建议加 `memo` / `useMemo` / `useCallback`」
  → 没有实测性能问题就是噪音，且误用 `useCallback` 会因依赖数组引入 bug。
- ❌ 「建议用 `DocumentFragment` 批量插入」
  → 需先证明这里是热路径且有实测数据。

## 5. 提交前自检项

- [ ] 每个 `async` 调用都有 `await` 或显式 `.catch()`？
- [ ] `try-catch` 是否真的包住了 `await`（而不是 Promise 的创建）？
- [ ] `await` 之间读到的共享状态，是否可能被别人改掉？
- [ ] 判空是否用了 `?.` / `??`？有没有被 falsy 误判（`0`、`''`）？
- [ ] 有没有 `==` 比较？
- [ ] 超过 `2^53` 的整数、金额浮点运算？
- [ ] `JSON.parse` / `JSON.stringify` 是否有 `try`？
- [ ] 数组排序是否给了比较函数？
- [ ] 定时器、事件监听、订阅是否在销毁时清理？
- [ ] 有没有提出"加锁"或要求 TS 类型的建议？（有就删掉）
