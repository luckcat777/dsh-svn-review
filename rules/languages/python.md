# Python 语言档案（L1）

> 配套 `../REVIEW_RULES.md`（L0 通用方法论）。本文件只管"在 Python 里什么算缺陷、什么算误报"。

---

## 1. 适用范围与版本约束

| 要确认 | 从哪看 | 影响什么 |
|---|---|---|
| Python 版本 | `pyproject.toml` 的 `requires-python`、`.python-version` | `X \| None`（3.10+）、`match`（3.10+）、`tomllib`（3.11+）能不能用 |
| 同步 or 异步 | 有无 `asyncio` / `async def` | 决定"阻塞调用"是不是缺陷 |
| 类型检查 | 有无 `mypy` / `pyright` 配置 | 决定类型注解是"强制"还是"注释" |

**不确定版本时，不要提 3.10+ 的语法。** 3.8 的代码提 `X | None` 直接编译不过。

## 2. 语言惯用法（判断"像不像问题"的前提）

- **失败用异常表达**，`None` 表示"没有这个值"，不是"出错了"。
- **`try/except` 宽泛捕获（`except Exception`）有时是有意的**——比如顶层兜底、清理路径。
- **`with` 管资源**是标准做法，看到 `with` 就不用再提"没关文件"。
- **鸭子类型**：不检查类型是常态，不要建议加 `isinstance` 护栏。
- **GIL 存在**：纯 Python 代码的多线程不能并行执行字节码，但 I/O 可以。

## 3. 常见确定性缺陷

### 3.1 可变默认参数
```python
def add(item, bucket=[]):   # ← 默认值只创建一次，跨调用共享
```
可证明缺陷，P1。

### 3.2 延迟绑定闭包
循环里创建的 lambda/函数捕获的是**变量**不是**值**，循环结束后全都指向最后一个值。

### 3.3 迭代时修改容器
在 `for x in lst` 里 `lst.remove(x)` / `lst.append(...)` → 跳过元素或死循环。

### 3.4 资源未关闭
没有 `with` 的文件、连接、锁。**但如果已经用了 `with`，此条不成立。**

### 3.5 数值与比较
- `/` 返回 float，`//` 才是整除；金额计算用 float 有精度问题（应看项目是否用 `Decimal`）。
- `is` 比较值：小整数和驻留字符串能"碰巧成立"，其它情况不成立。

### 3.6 异步
- `async def` 里调用阻塞函数（`requests`、`time.sleep`、同步 DB 驱动）→ 卡住整个事件循环。
- `await` 之间状态被别的任务改掉（同 JS 的交错问题）。

## 4. 误报清单（★ 最常被误提的）

- ❌ **"建议加类型注解 / 用 dataclass / 用 pydantic"** → 设计偏好，不是缺陷。
- ❌ **"`except Exception: pass` 吞异常"** → 先看它是不是清理路径或顶层兜底；说不出后果就是 P2。
- ❌ **"建议改成列表推导式"** → 可读性偏好，P3。
- ❌ **"多线程写这个变量不安全"** → 需先证明有并发写；GIL 下简单赋值本身是原子的，别一概而论。
- ❌ **"建议用 `asyncio` 重写"** → 架构级建议，超范围。
- ❌ **"全局变量不好"** → 设计偏好。
- ❌ **"`import *` 不好"** → P3，且可能是项目既有约定。
- ❌ **"这个循环太慢，建议用 numpy"** → 需有实际数据量证据。
