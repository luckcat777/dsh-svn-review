# dsh-svn-review

把代码审查钉死在 SVN 的真实改动上。

它只做一件事：让 Agent 在动手之前先拿到「这次到底改了哪些文件」，而不是靠猜、靠翻整个仓库。拿到清单之后，那几行字就成了本次允许修改的边界——范围外的文件，即使是明显的问题，也只报告、不修改。

## 为什么需要它

SVN 的改动集通常藏在图形界面里：TortoiseSVN 的提交对话框、右键菜单的「检查修改」。命令行 `svn status` 能给出同样的答案，但很多机器上只装了图形壳，`svn.exe` 根本不在 PATH 里。

而 Agent 恰恰最需要这份清单。没有它，你只能把整段规则复述一遍、再祈祷它别越界；有了它，越界就变成一个可以被工具检查的事实。

本插件直接解析工作副本里的 `.svn/wc.db`（SQLite），比对 `.svn/pristine/` 中的基线副本，等价于 `svn status`，但完全离线、不需要任何外部程序。

## 安装

```sh
dsh plugin --profile web add dsh-svn-review
```

装完刷新页面即可，通常不需要重启。

## 用到的东西

| 名称 | 类型 | 说明 |
|---|---|---|
| `svn_change_set` | 工具 | 返回工作副本的变更集：`M` 已修改、`A` 本地新增、`D` 已删除、`!` 文件缺失、`C` 冲突 |

参数只有一个，还常常不用传：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 否 | 工作副本内的任意目录，会向上自动寻找 `.svn/wc.db`。省略时用当前工作目录 |

返回内容包括工作副本根目录、基线版本号、各状态计数，以及逐个文件的路径。

## 输出示例

```
工作副本 E:\x_japan（基线 r1129519）：M=1 A=0 D=0 !=0 C=0
 M  hitalk-h5-gameserver/src/main/java/.../ContinuouslyPushGiftActivityScript.java
```

## 判定方式

`.svn/wc.db` 的 `NODES` 表为每个受控文件记录了基线校验和与上次提交时的快照（大小、mtime）。

1. 文件不在了 → `!`
2. 大小和快照不同 → `M`，直接判定，不读文件内容
3. 大小与 mtime 都和快照一致 → 跳过，认为没动过
4. 大小相同但 mtime 不同 → 计算 SHA-1 与基线校验和比对，确认后才判定 `M`

第 3 步是关键：一个几千个文件的工作副本如果逐个算哈希要十几秒，走快路径通常不到一秒。第 4 步保证「改了但长度没变」的编辑不会漏掉。

`A` / `D` 来自 `op_depth > 0` 的节点，冲突来自 `ACTUAL_NODE`。

## 限制

- 不返回 `?`（未纳入版本控制的文件）。这类文件进不了本次提交，不构成修改范围。
- 不生成 diff。文件清单拿到之后，读文件用 Agent 自己的工具即可，比在插件里造一份 diff 更省事也更准确。
- 依赖 Node 内置的 `node:sqlite`（Node 22.5+，23.4 之后无需实验开关）。宿主 Node 太旧时，工具会明确说明而不是抛一个 SQLite 栈。
- 只读 `.svn/wc.db`，不写入工作副本的任何位置。
